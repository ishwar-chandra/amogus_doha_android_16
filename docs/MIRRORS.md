# doha-roms device mirrors (`mirrors/`) — offline-proofing the device code

## The problem this solves

The kit's manifest (`default.xml`) pins **1,184 projects**. 1,157 of them come
from LineageOS / AOSP — permanent, mirrored-everywhere infrastructure that has
never disappeared in Android's history. The remaining **27 projects are the
device-specific ones** (device trees, kernel, vendor blobs, Qualcomm
opensource trees) — and they live in *personal community GitHub accounts*:

| Upstream | Projects | Status (checked 2026-10-17) |
|---|---|---|
| `moto-common/*` | 15 | **ALL ARCHIVED Apr 4, 2026** (read-only, deletable any day) |
| `Aldair402/*` | 8 | active — kernel/common last touched 2026-06 |
| `AOSPA/*` | 3 | active (uvite branches) |
| `ThankYouMario/*` | 1 | active — last commit 2026-09-03 |

Two more facts from the live check:

* **Every one of the 27 pins is still the branch tip** (`PIN=tip` for all 27).
  The upstreams have *not moved past our pins* — the recipe is frozen anyway.
* Archived repos can be **deleted by their owner at any time**. An owner
  account deletion (or a DMCA / repo cleanup) takes all pins with it — and
  `repo sync` would then fail, killing the build forever.

## The solution: vendor + restore

```
mirrors/
  repos/<project>.tgz     27 self-contained git mirrors (bare repo tarball:
                          the pinned commit + its complete reachable history)
  repos/<project>.fact    one line of metadata per repo (sha, date, size, url)
  MIRRORS.tsv             merged table (name|path|remote|sha|date|url|size)
  git/                    (generated by restore) usable bare git repos
  vendor.log              transcript of the last vendor run
```

**Vendor (one-time, ~0.5–1.5 GB download, resumable):**

```bash
bash scripts/vendor-mirrors.sh        # or: bash doha.sh vendor   (menu 11)
```

For each of the 27 projects it fetches *exactly the pinned commit* and its
history (no pull-refs, no noise), then stores it as a tarball **inside this
repo**. Commit the `mirrors/` directory so the code is inside the repo
history, not referenced.

**Restore (automatic — you never run it by hand):**

`lineage-16/build.sh` calls `scripts/restore-mirrors.sh` by itself between
`repo init` and `repo sync` whenever `mirrors/MIRRORS.tsv` + tarballs exist:

1. untars each `mirrors/repos/*.tgz` into `mirrors/git/<project>` (bare repos)
2. sets `uploadpack.allowAnySHA1InWant` on each
3. writes `$SRC/.repo/local_manifests/doha-mirror.xml`, which
   `<remove-project>`s the 27 upstream entries and re-adds them pointing at
   `file://…/mirrors/git` with the **same pinned SHAs**

After that, `repo sync` fetches the 27 device projects from **this repo on
your disk** — verified bit-for-bit identical to upstream (tested: mirror
checkout == upstream checkout, `diff -r` clean). Even if every community
upstream is deleted tomorrow, sync + build still work.

To force upstream again (e.g. after a pin bump): delete
`$SRC/.repo/local_manifests/doha-mirror.xml` and remove `mirrors/`.

## Size guidance ("how much code is OK to clone") — MEASURED

Complete 27-repo vendor set = **3.4 GB** (2026-10-17 run, 27/27, zero
failures):

| Repo | Size | | Repo | Size |
|---|---|---|---|---|
| kernel msm-4.14 | 1483 MB | | 23 small repos (trees, qcom opensource) | ~105 MB |
| proprietary qcom common blobs | 1430 MB | | **TOTAL** | **~3.4 GB** |
| prebuilt clang r383902 | 259 MB | | vendor/motorola/amogus blobs | 116 MB |

How to store 3.4 GB safely:

* **Git**: commit the mirrors in **3 separate commits and push after each**
  (git refuses single pushes whose pack exceeds ~2 GB): ① kernel alone,
  ② proprietary blobs alone, ③ everything else. GitHub warns above ~1 GB
  but works; your 5 TB GDrive holds a second copy.
* **Why not the whole 1,184-project source in one repo?** That would be
  ~200 GB, cannot be pushed/cloned, and breaks the `repo`-tool/Soong build
  model (per-project git checkouts driven by the manifest). The 1,157
  platform pins live on permanent infrastructure (googlesource + LineageOS
  + countless mirrors) — they have never disappeared.
* The delivered chat zip carries the **23 small mirrors (95 MB)**; the 4
  big tarballs regenerate on your machine in ~10–15 min with
  `bash doha.sh vendor` (resumable — finished repos are skipped).

## Legal note

`mirrors/repos/*.tgz` for the `vendor/*` and `proprietary_*` projects
contain **proprietary Motorola/Qualcomm blobs** (already publicly hosted by
the community trees this kit pins). Keep them for personal backup, but if
you publish the kit, **keep the repo private** or strip `mirrors/` first
(GitHub routinely takes down public blob dumps).

## Refreshing pins later

1. Edit the `<project …>` line in `default.xml` (bump `revision`).
2. Delete the stale `mirrors/repos/<project>.tgz` + `.fact`.
3. `bash scripts/vendor-mirrors.sh` re-fetches just that repo; the TSV and
   the generated local manifest follow automatically.
4. Commit both `default.xml` and the new tarball together.
